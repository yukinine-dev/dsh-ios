# DshPanel — iOS-обёртка над dsh web

Тонкое приложение: полноэкранный WKWebView, который открывает dsh web (тот же адрес,
что печатает `dsh web` и что ты уже вставляешь в Telegram-бота через `/token`), плюс
кнопки назад/обновить и экран настроек для адреса. Никакого переизобретения UI — это
буквально та же панель, что в браузере, просто в виде отдельного приложения на экране.

Собирается в GitHub Actions (macOS-раннер) — свой Mac не нужен.

## 1. Доступ из любой точки — Tailscale

dsh web слушает только локально (127.0.0.1:3080), так что "из любой точки" значит —
нужна приватная сеть между телефоном и компом:

1. На компе: `curl -fsSL https://tailscale.com/install.sh | sh` (Linux) затем `tailscale up`.
2. На iPhone: приложение **Tailscale** из App Store, залогиниться тем же аккаунтом.
3. На компе смотришь свой Tailscale-адрес: `tailscale ip -4` (что-то вроде `100.x.x.x`).
4. `dsh web` печатает адрес с токеном на `127.0.0.1` — поменяй host на свой Tailscale IP,
   например было `http://127.0.0.1:3080/?token=abc`, станет `http://100.x.x.x:3080/?token=abc`.
   Если `dsh web` слушает только 127.0.0.1 и не пускает по Tailscale IP — запускай его с
   `--host 0.0.0.0` (или как у тебя называется этот флаг; проверь `dsh web --help`).

Токен меняется при каждом перезапуске `dsh web` — просто вставляй новую строку в настройках
приложения, пересборка не нужна (то же самое ты уже делаешь с `/token` в Telegram-боте).

## 2. Собрать IPA в GitHub Actions

1. Создай **приватный** репозиторий на GitHub (приватный — потому что внутри в целом
   ничего секретного, но зачем светить лишнее).
2. Залей туда все файлы из этой папки (`project.yml`, `Sources/`, `.github/workflows/build-ipa.yml`, этот README) как есть, сохраняя структуру.
3. Запушь в `main` — экшен запустится сам (или зайди в Actions → Build IPA → Run workflow,
   если нужно запустить руками).
4. Через пару минут в Actions → (твой запуск) → Artifacts будет `DshPanel-ipa` — скачай,
   внутри `DshPanel.ipa`.

## 3. Поставить на телефон

IPA несигнированный (специально — сертификата Apple Developer тут нет и не нужен).
Ставь через **LiveContainer**, как ты уже делаешь с другими приложениями — просто
импортируй `DshPanel.ipa` туда.

## 4. Первый запуск

Открой приложение → появится экран настроек → вставь полный адрес с токеном
(`http://100.x.x.x:3080/?token=...`) → Готово. Дальше это просто dsh web в полноэкранном виде.

## Уведомления и Live Activity — что реально работает сейчас

В приложении есть свой клиент dsh-web event-stream (`DshEventsClient.swift`) — он
независимо от WebView открывает тот же `$events` WebSocket, что и Telegram-бот, и следит
за статусом сессии (свободна / думает / ждёт подтверждения). На значимых переходах:

- показывается **локальное уведомление** (`UNUserNotificationCenter`, без APNs,
  разрешение запрашивается при первом запуске);
- ведётся **Live Activity** (экран блокировки + Dynamic Island) через виджет-расширение
  `DshActivityWidget` — старт/обновление/завершение целиком локальные, через `ActivityKit`
  без push-обновлений.

Это именно то, что ты увидел у Husk при создании пары — `UNUserNotificationCenter` и
локальный `Activity.request/update/end` не требуют Apple Developer аккаунта и работают на
обычном резейл-сертификате для Feather, потому что не трогают APNs вообще.

**Честные границы этого режима:**

- Работает, пока приложение **живо** — открыто на экране или недавно свёрнуто (iOS
  ненадолго держит процесс активным после сворачивания; конкретное время не
  гарантировано и решается системой). Если приложение не запускалось давно или было
  выгружено системой из памяти, обновлений не будет — локальный WebSocket-клиент просто
  не работает, когда процесса нет.
- Это **не** "пришло уведомление, пока телефон пролежал в кармане час" — для такого
  нужен настоящий push через APNs, см. ниже.
- Live Activity автоматически завершается через 15 секунд после перехода в "свободна",
  чтобы не висела вечно на экране блокировки.

Если нужен канал, который долетает всегда независимо от того, запущено ли приложение —
Telegram-бот (`dsh_tg_bridge.py`) уже это делает сегодня через обычный Telegram push, это
не отменяется и остаётся основным способом узнать об одобрении/готовности издалека.
DshPanel с его локальными уведомлениями — это бонус для случая "приложение и так открыто
или недавно было открыто".

## Настоящий push и remote Live Activity — требует Apple Developer аккаунт

Это следующий уровень, отдельный от того, что уже работает выше, и зависит от того,
какой у тебя сертификат:

- **Push-уведомления на APNs** и **remote-обновления Live Activity** (когда статус
  обновляется, даже если приложение полностью закрыто/выгружено) требуют, чтобы
  приложение было подписано ключом/сертификатом настоящего Apple Developer аккаунта
  (платного, $99/год) с entitlement `aps-environment`, привязанным к конкретному Team ID
  и **не wildcard** App ID (`TEAMID.*` для push не подходит — Apple это прямо запрещает).
- Проверить, подходит ли твой купленный сертификат: `openssl smime -verify -in
  profile.mobileprovision -inform der -noverify -out profile.plist`, затем посмотри в
  `profile.plist` на `application-identifier` (wildcard или конкретный bundle id?) и на
  наличие `aps-environment` в `Entitlements`. Если там wildcard — push в принципе не
  заработает, какой угодно код не поможет; если конкретный bundle id и есть
  `aps-environment` — реальный push возможен.
- Если окажется, что возможен — дальше нужен App ID с push-capability в Apple Developer
  портале, `.p8`-ключ для APNs, и бэкенд, который шлёт push (логичное место — дописать в
  сам `dsh_tg_bridge.py`, он и так видит все события в реальном времени).

Пришли вывод `openssl` — скажу однозначно, тянет твой сертификат на настоящий push или
нет.
